# Security contract

M1 is a local, single-operator, synthetic-data application. It is not production certified.

## Defense in depth

1. Docker publishes SQL, FastAPI and Streamlit only on IPv4 loopback. A unique bearer token protects
   API operations. The local frontend represents the single trusted desktop operator.
2. Cloud configuration rejects local authentication, SQL passwords/certificate bypass and Azure
   OpenAI API keys. The API validates Entra RS256 signatures, issuer, audience, expiry, tenant,
   explicit user object IDs and delegated scope. Client-supplied identity headers have no authority.
3. The model can call only `propose_query`; structured output is an input contract, not authorization.
4. The gateway requires exactly one SELECT, an approved positive AST vocabulary, scoped column
   resolution, allowlisted views and a reviewed join. No DML, DDL, stored procedures, system tables,
   three/four-part names, dynamic SQL, external data sources, comments, hints or unsupported functions.
5. Approved JOINs are vJobs/vJobFinancials → vCustomers on CustomerId, and jobs → a ranked-invoice
   relation on unchanged JobId AND rank = 1. The latter requires ROW_NUMBER partitioned only by JobId,
   InvoiceId in its ordering, passthrough columns and no grouping/join inside the ranked relation.
   RANK/DENSE_RANK, key spoofing and missing/disjunctive rank predicates cannot authorize that join.
   CTEs and uncorrelated subqueries can compose reads; other derived/CTE joins require future review.
   No UNION, recursive CTEs, correlated subqueries, wildcard projection or SELECT INTO.
6. Parameters are typed and bound separately through ODBC. Repeated names preserve rendering order.
   User values cannot inject structure. Every subsequent proposal and practice query is revalidated.
7. The runtime principal has explicit SELECT grants on existing approved objects, not the reporting
   schema. Base SELECT/DML, reporting DML, EXECUTE and creation/schema-management permissions are denied.
   Startup rejects a mismatched principal, db_owner/sysadmin, base access or missing reporting access.
8. Default bounds: 12,000 SQL characters, 400 AST nodes, eight SELECTs, 20 parameters, three concurrent
   requests/queries, ten seconds per statement, 500 result rows and 256 KiB result payload.
   No automatic TOP insertion. Excess results fail instead of being presented as complete answers.
9. Conversation IDs are generated by the server and bound to the authenticated subject. Clients cannot
   supply arbitrary histories or roles. Accepted questions/proposals are retained in bounded process
   memory; result cells and rejected proposals are excluded. Expiry/capacity failures are explicit.
   Every proposal, including one generated from earlier context, still traverses the same gateway.

## Secrets and identities

`scripts.init_local` generates random local passwords and an API token; `.env` is ignored by Git and
Docker. Never print or commit it. Local developers can access it, so the local profile is not a
multi-user security boundary. The migration container receives the administrator password; backend
and frontend containers receive only their required credentials. Migrations use neither the model
nor any HTTP route. Cloud runtime explicitly uses ManagedIdentityCredential.

The query API never accepts a connection string, table grant, schema catalog or policy from a user.
Database strings are not fed back to the model. Grounded summaries are plain text. Frontend has no SQL
credentials. Model errors and database failures return sanitized messages, not stack traces or raw
provider/connection data. Audit events contain request ID, subject hash, query hash, row count and
timing; SQLGlot fallback logs containing raw SQL are suppressed.

## Supported-language limits

Rejecting a query does not mean it is intrinsically malicious; it may be outside the reviewed subset.
The parser is not the sole security boundary: actual SQL principal tests demonstrate denied access.
SQL validation cannot prove business intent, inference resistance or arbitrary metric correctness.
An expensive allowed query can still consume resources before cancellation. Use database workload
controls, distributed rate limits and operational monitoring before broader deployment.

M2 requires live identity/network validation and a delegated cloud frontend. M4 requires row-level
security, per-user data scopes, durable audit export, request budgets, security assessment, dependency
auditing and incident procedures. See [THREAT_MODEL.md](THREAT_MODEL.md).
